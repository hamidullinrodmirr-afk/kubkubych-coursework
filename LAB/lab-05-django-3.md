## 1. verbose_name и verbose_name_plural

### Что это

Метаданные задают имя одного объекта и название списка объектов.

### Где находится

[products/models.py](../products/models.py) — Product.Meta.

### Основной код

~~~python
class Meta:
    ordering = ('name',)
    verbose_name = 'набор'
    verbose_name_plural = 'наборы'
~~~

### Как работает

В административной части Product представляется как «набор», список — как «наборы». Они не переименовывают таблицу SQL. Явные метаданные также есть у Category, User, CartItem, Order, Review, SiteSetting. У Favorite и OrderItem явные verbose_name/plural не заданы, используются автоматически полученные имена.

### Визуализация

~~~text
Product → набор
Список Product → наборы
~~~

Состояние требования: Реализовано не для всех моделей: у Favorite и OrderItem явные названия отсутствуют.

## 2. ImageField

### Что это

Поле модели связывает запись с загруженным изображением.

### Где находится

[products/models.py](../products/models.py) — Product.image и Category.image.

### Основной код

~~~python
image = models.ImageField('Изображение', upload_to='products/', blank=True, null=True)
~~~

### Как работает

Product использует products/, Category — categories/. При стандартном локальном хранилище файл располагается внутри MEDIA_ROOT, а база хранит относительный путь. blank=True позволяет не загружать изображение. Pillow подключена в requirements.txt. Приём файла формой разобран в ЛР-4.

### Визуализация

~~~text
Форма → файл → media/products/…
Product.image → путь
~~~

Состояние требования: Реализовано в коде.

## 3. Django session

### Что это

Сессия позволяет связывать последовательные запросы браузера с состоянием на сервере.

### Где находится

[kubkubych/settings.py](../kubkubych/settings.py) — MIDDLEWARE.

### Основной код

~~~python
'django.contrib.sessions.middleware.SessionMiddleware',
'django.contrib.auth.middleware.AuthenticationMiddleware',
~~~

### Как работает

SessionMiddleware подключает request.session, AuthenticationMiddleware восстанавливает пользователя. Стандартный вход Django Admin использует сессию; products/site_views.py проверяет request.user и роль. Cookie содержит идентификатор сессии, а не пароль. JWT покупателей — отдельный механизм: токен API не превращается автоматически в сессионный вход для /manage/products/.

### Визуализация

~~~text
Вход Admin → сессионная cookie
Следующий запрос → request.user → проверка роли
~~~

Состояние требования: Сессионная инфраструктура и авторизация используются. Собственное присваивание request.session['…'] в текущем коде не реализовано.

## 4. Перенаправление

### Что это

Перенаправление отправляет браузер на другой адрес вместо выдачи HTML текущего действия.

### Где находится

[products/site_views.py](../products/site_views.py) — product_create / product_update / product_delete.

### Основной код

~~~python
return HttpResponseRedirect(reverse('product-manage-list'))
~~~

### Как работает

После успешного POST браузер получает redirect на список. Обновление списка повторяет GET, а не POST сохранения. reverse получает адрес из имени маршрута. В users/oauth.py также применяется функция redirect при переходах OAuth; эти переходы зависят от внешней конфигурации.

### Визуализация

~~~text
POST формы → сохранение → 302 → GET списка
~~~

Состояние требования: Реализовано в коде.

## 5. inlines: позиции внутри заказа

### Что это

Inline размещает связанные дочерние объекты внутри формы родителя.

### Где находится

[orders/admin.py](../orders/admin.py) — OrderItemInline и OrderAdmin.inlines.

### Основной код

~~~python
class OrderItemInline(admin.TabularInline):
    model = OrderItem
    extra = 0
    readonly_fields = ('product', 'product_name', 'product_article', 'unit_price', 'quantity')
    can_delete = False

# В классе OrderAdmin:
inlines = (OrderItemInline,)
~~~

### Как работает

OrderItem связан с Order внешним ключом. TabularInline показывает позиции таблично, перечисленные поля доступны только для чтения, удаление строк выключено, лишние пустые строки не добавляются. Здесь показаны два фрагмента admin.py, а не отдельный исполняемый модуль.

### Визуализация

~~~text
Заказ: номер, статус, сумма
Позиции:
  товар | артикул | цена | количество
~~~

Состояние требования: Реализовано в коде.

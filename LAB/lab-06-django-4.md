### Общая логика

## 1. Формирование PDF в административной части

### Что это

PDF создаётся на сервере из данных товаров, выбранных в Django Admin.

### Где находится

[products/admin.py](../products/admin.py) — ProductAdmin.export_specs_pdf.

### Основной код

~~~python
response = HttpResponse(content_type='application/pdf')
response['Content-Disposition'] = 'attachment; filename="product-specifications.pdf"'
pdf = canvas.Canvas(response)
y = 800
pdf.setTitle('Product specifications')
for product in queryset.order_by('name'):
    pdf.drawString(40, y, f'{product.article}: {product.name}; stock={product.stock}; price={product.price}')
    y -= 24
    if y < 60:
        pdf.showPage()
        y = 800
pdf.save()
return response
~~~

### Как работает

HttpResponse объявляет тип PDF, Content-Disposition предлагает скачивание с указанным именем. ReportLab пишет документ в ответ. Товары сортируются по имени; для каждого выводятся артикул, название, остаток и базовая цена, не final_price. Координата y уменьшается после каждой строки; у нижней границы начинается новая страница. pdf.save завершает документ. Загруженный specification_file не читается. Используется стандартный шрифт без явной настройки кириллицы, длинные строки не переносятся.

### Визуализация

~~~text
Выделить товары в Admin
        ↓
Действие формирования PDF
        ↓
Данные Product → строки ReportLab → PDF-ответ
        ↓
Скачать product-specifications.pdf
~~~

Состояние требования: Генератор реализован. Качество кириллицы, длинных строк и итогового документа визуально не проверено.

## 2. FileField: файл спецификации

### Что это

FileField связывает объект с файлом в хранилище.

### Где находится

[products/models.py](../products/models.py) — Product.specification_file.

### Основной код

~~~python
specification_file = models.FileField(
    'Спецификация', upload_to='product-specifications/', blank=True
)
~~~

### Как работает

В базе сохраняется относительное имя файла, само содержимое размещается в хранилище. upload_to задаёт подкаталог, blank=True позволяет оставить поле пустым. Это произвольный файл: название «Спецификация» и подсказка про PDF не ограничивают формат исключительно PDF. В объявлении нет собственного ограничения расширения или размера.

### Визуализация

~~~text
Загрузка → media/product-specifications/имя-файла
База → product-specifications/имя-файла
~~~

Состояние требования: Реализовано в коде.

## 3. URLField: внешняя ссылка

### Что это

URLField хранит адрес ресурса, а не загруженный файл.

### Где находится

[products/models.py](../products/models.py) — Product.image_url.

### Основной код

~~~python
image_url = models.URLField('Ссылка на изображение', blank=True)
~~~

### Как работает

Поле служит для ссылки на изображение. При проверке ModelForm используется проверка формата URL. Само поле не скачивает файл, не проверяет, доступен ли ресурс сейчас, и не гарантирует, что по ссылке находится картинка. blank=True делает ссылку необязательной.

### Визуализация

~~~text
Ввод URL → проверка формата → строка в базе
Скачивание изображения этим полем → не выполняется
~~~

Состояние требования: Реализовано в коде.

## 4. Как форма передаёт файл серверу

### Что это

Текстовые поля и загруженные файлы поступают в разные части запроса.

### Где находится

[products/site_views.py](../products/site_views.py) — product_create и product_update.

### Основной код

~~~python
form = ProductForm(request.POST or None, request.FILES or None)
if request.method == 'POST' and form.is_valid():
    product = form.save(commit=True)
~~~

### Как работает

request.POST содержит поля, request.FILES — файлы. ProductForm получает оба набора, проверяется и сохраняет модель. В templates/products/manage_form.html указаны method="post" и enctype="multipart/form-data", без которого браузер не передаст содержимое загрузки обычным способом. При редактировании дополнительно передаётся instance=product.

### Визуализация

~~~text
HTML multipart POST
  ├─ текст → request.POST
  └─ файлы → request.FILES
              ↓
        ProductForm → проверка → сохранение
~~~

Состояние требования: Реализовано в коде.

## Вопрос 2. Локализация и часовой пояс

### Что это

Настройки определяют язык стандартных сообщений и обработку времени.

### Где находится

[kubkubych/settings.py](../kubkubych/settings.py) — Язык и время.

### Основной код

~~~python
LANGUAGE_CODE = 'ru-ru'
TIME_ZONE = 'Europe/Moscow'
USE_I18N = True
USE_TZ = True
~~~

### Как работает

USE_I18N включает механизм переводов Django, LANGUAGE_CODE задаёт русский язык по умолчанию. TIME_ZONE и USE_TZ относятся к времени, а не переводу текста. Русские подписи в моделях написаны явно. Эти настройки не переводят автоматически любой авторский текст и не добавляют кириллический шрифт в PDF.

### Визуализация

~~~text
Django → русские стандартные подписи
ReportLab → отдельная настройка шрифта
~~~

Состояние требования: Настройки локализации есть. Собственные каталоги переводов в этом отчёте не заявляются.

## Вопрос 3. Как устроена раздача media?

### Что это

media — загруженные пользователями файлы; это не статические CSS и JS проекта.

### Где находится

[kubkubych/urls.py](../kubkubych/urls.py) — Ветка settings.DEBUG.

### Основной код

~~~python
if settings.DEBUG:
    urlpatterns += static(settings.MEDIA_URL, document_root=settings.MEDIA_ROOT)
~~~

### Как работает

В settings.py MEDIA_ROOT=BASE_DIR / 'media' задаёт физический каталог, MEDIA_URL='/media/' — адресный префикс. В DEBUG добавлена локальная раздача файлов через Django. Эта ветка предназначена для разработки, не заменяет настройку раздачи файлов при production-развёртывании.

### Визуализация

~~~text
URL /media/products/… → файл в MEDIA_ROOT/products/…
~~~

Состояние требования: Реализовано в коде.

## Вопрос 4. Что даёт настройка кэша?

### Что это

Кэш позволяет временно сохранять результаты, чтобы не вычислять их повторно.

### Где находится

[kubkubych/settings.py](../kubkubych/settings.py) — CACHES.

### Основной код

~~~python
CACHES = {
    'default': {
        'BACKEND': 'django.core.cache.backends.locmem.LocMemCache',
        'LOCATION': 'kubkubych-local-cache',
    }
}
~~~

### Как работает

LocMemCache хранит значения в памяти текущего процесса, не является общим хранилищем всех серверных процессов. Конфигурация лишь предоставляет backend: для использования нужны обращения к API кэша или кэширование представлений. В прикладном коде отдельные cache.get/set или cache_page не обнаружены; ускорение страниц кэшем не подтверждено.

### Визуализация

~~~text
Backend настроен
        ↓
Прикладное сохранение результата → не обнаружено
~~~

Состояние требования: Инфраструктура есть; фактическое прикладное кэширование не реализовано.

## Результат и вывод

В проекте есть FileField, URLField, передача загрузок через ModelForm и генерация PDF административным действием. PDF строится из полей модели, не из содержимого загруженных спецификаций. Ограничения: нет визуальной проверки PDF, явного кириллического шрифта и переноса длинных строк; отдельный сценарий применения кэша отсутствует.

## Демонстрация в интерфейсе

Для демонстрации PDF нужно открыть список товаров в Django Admin, отметить несколько записей, выбрать действие «Сформировать PDF со спецификациями выбранных наборов» и выполнить его. Затем открыть скачанный документ и проверить текст, кириллицу, длинные названия и несколько страниц. Для загрузки спецификации следует открыть форму товара, выбрать файл, сохранить запись и проверить доступность файла по ссылке. Это описание ручной демонстрации, а не утверждение о её выполнении.

Реальные авторизованные скриншоты в эту редакцию не включены. Наличие реализации подтверждается кодом; качество UI и содержимого файлов требует отдельной ручной проверки.

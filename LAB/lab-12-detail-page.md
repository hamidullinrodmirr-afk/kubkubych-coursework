# Отчёт по лабораторной работе 12
## Страница товара и управление объектом

### Цель работы
Описать переход к отдельному товару, загрузку его данных и HTML-интерфейс управления сущностью.

### Маршрут и загрузка
Маршрут products/<str:slug>/ связан с ProductDetailView. Представление передаёт slug в catalog/detail.html. JavaScript выполняет:
~~~javascript
const data = await API.get(
    '/products/?slug=' + encodeURIComponent(slug)
);
const list = data && (data.results || data);
currentProduct = list[0];
~~~

При отсутствии результатов выводится сообщение «Набор не найден». При наличии объекта строится блок характеристик, цена, изображение, кнопки корзины и избранного. Отзывы загружаются отдельным /api/products/{id}/reviews/.

### Сериализаторы и граница реализации
ProductListSerializer передаёт характеристики, серию, цену, наличие и агрегаты. ProductDetailSerializer дополнительно содержит description, даты и одобренные отзывы.

Текущий HTML использует запрос списка по slug, а не retrieve по ID. Поэтому описание, которое шаблон пытается вывести, отсутствует в полученной сокращённой сериализации. Это обнаруженное расхождение; его устранение не заявляется в данном отчёте.

### HTML CRUD
/manage/products/ содержит список и маршруты создания, изменения и удаления. ModelForm передаёт объект через instance при изменении и принимает request.FILES. Доступ ограничен сессионным пользователем с ролью admin.

Удаление выполняется POST после подтверждения. Товары, связанные с OrderItem через PROTECT, не могут быть свободно удалены; необработанная защищённая связь может вызвать ошибку вместо пользовательского сообщения.

### Результат и вывод
Реализованы адрес товара по slug, клиентский блок характеристик и отдельный HTML CRUD. Архитектура разделяет HTML-оболочку и API. Зафиксированы два ограничения: неполная загрузка описания на карточке и отсутствие отдельной обработки защищённого удаления.

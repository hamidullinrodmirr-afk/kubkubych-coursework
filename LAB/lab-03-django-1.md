# Отчёт по лабораторной работе 3

## Базовые возможности Django

### Цель и основание разбора

Разобрать условия лабораторной работы на реализации интернет-магазина «КубКубыч»: объяснить назначение каждого средства, показать место в коде и последовательность его работы.

Источник условий — раздел «Весна 2026» [курса СДО](https://online.mospolytech.ru/course/view.php?id=15327), перечень, ранее зафиксированный при разборе курса. Повторная сверка авторизованной страницы при подготовке этой редакции не выполнялась. Нумерация ниже служит для объяснения пунктов и не является дословным воспроизведением страницы.

Разбор выполнен по текущему исходному коду. Фрагменты сокращены до существенных строк; схемы — поясняющие иллюстрации с условными значениями, не скриншоты и не протокол браузерных тестов. Исходный код при подготовке отчёта не изменялся.

### Общая логика

Модель описывает данные, QuerySet выбирает их, представление обрабатывает запрос, а шаблон формирует HTML. В магазине публичные страницы также получают данные через REST API; серверный список управления товарами — отдельный сценарий.

## 1. __str__: понятное имя объекта

### Что это

Метод определяет, каким текстом объект представляется человеку.

### Где находится

[products/models.py](../products/models.py) — Product.__str__.

### Основной код

~~~python
def __str__(self) -> str:
    return f'{self.article} — {self.name}'
~~~

### Как работает

Вместо технического Product object показывается артикул и название. Это не изменение данных в базе, а их текстовое представление.

### Визуализация

~~~text
Объект Product → «артикул — название» → подпись в интерфейсе
~~~

Состояние требования: Реализовано в коде.

## 4. choices: ограниченный набор вариантов

### Что это

choices связывает машинные значения с понятными подписями.

### Где находится

[orders/models.py](../orders/models.py) — Order.Status и поле status.

### Основной код

~~~python
class Status(models.TextChoices):
    NEW = 'new', 'Новый'
    PROCESSING = 'processing', 'В обработке'
    SHIPPED = 'shipped', 'Передан в доставку'
    DELIVERED = 'delivered', 'Доставлен'
    CANCELLED = 'cancelled', 'Отменён'
~~~

### Как работает

Поле status использует Status.choices. В базе хранится new, а форма предлагает «Новый». Допустимые переходы между статусами проверяет отдельный set_status: choices сами не описывают последовательность переходов.

### Визуализация

~~~text
Значение new ↔ подпись «Новый»
~~~

Состояние требования: Реализовано в коде.

## 5. related_name: обратная связь

### Что это

Это имя, по которому можно получить объекты с обратной стороны связи.

### Где находится

[products/models.py](../products/models.py) — Product.category.

### Основной код

~~~python
category = models.ForeignKey(Category, on_delete=models.PROTECT,
~~~

### Как работает

У товара есть category, а у серии появляется products. Так можно перейти от одной серии к её товарам. Аналогично Order.items и Product.reviews.

## 10. Собственный менеджер

### Что это

Менеджер объединяет операции создания и получения объектов модели.

### Где находится

[users/managers.py](../users/managers.py) — UserManager.create_user.

### Основной код

~~~python
def create_user(self, email: str, password: str | None = None, **extra_fields: Any):
    if not email:
        raise ValueError('Email обязателен')
    user = self.model(email=self.normalize_email(email), **extra_fields)
    user.set_password(password)
    user.save(using=self._db)
    return user
~~~

### Как работает

UserManager создаёт пользователя с email, нормализует адрес и передаёт пароль в set_password для хеширования. create_superuser дополнительно задаёт административные признаки. Это менеджер пользовательской модели, а не отдельный класс представления.

### Визуализация

~~~text
Данные регистрации → менеджер → пользователь в базе
~~~

Состояние требования: Реализовано в коде.

## 15. Пагинация с try/except

### Что это

Пагинация делит длинный список на небольшие страницы.

### Где находится

[products/site_views.py](../products/site_views.py) — product_manage_list.

### Основной код

~~~python
paginator = Paginator(queryset, 10)
try:
    products = paginator.page(request.GET.get('page', 1))
except PageNotAnInteger:
    products = paginator.page(1)
except EmptyPage:
    products = paginator.page(paginator.num_pages)
~~~

### Как работает

По десять товаров выводится на странице. Нечисловой page возвращает первую, номер вне диапазона — последнюю. Это пагинация HTML-управления, не описание механизма DRF.

### Визуализация

~~~text
page=abc → первая
page вне диапазона → последняя
~~~

Состояние требования: Реализовано в коде.

## Ответы на контрольные вопросы

### Что такое миграции?

Миграции фиксируют изменения схемы моделей и применяются командой python manage.py migrate. showmigrations показывает применённые шаги. Они находятся в каталогах migrations приложений; создание файла миграции и её применение — разные действия.

### Что такое QuerySet?

Это объект выборки Django ORM. filter, exclude и order_by уточняют запрос; обычный QuerySet ленивый и выполняется при потреблении результата, например при переборе. Это не готовый список Python.

### Как устроены URL и регулярные выражения?

В kubkubych/urls.py и products/site_urls.py используются path и конвертеры <str:slug>, <int:pk>. Регулярные маршруты можно описывать re_path, но в рассмотренных маршрутах проекта он не используется. RegexValidator в orders/models.py проверяет значения полей и не является URL-маршрутом.

## Результат и вывод

Рассмотрены базовые средства моделей, ORM, URL, шаблонов и регистрации. Главное незакрытое условие — три собственных template tags. Использованы два встроенных фильтра; требование именно собственных фильтров нужно отличать от требования любых двух фильтров.

# Отчёт по лабораторной работе 3
## Базовые возможности Django

### Цель работы
Рассмотреть модели, выборки ORM, маршрутизацию, регистрацию и работу с изображениями в веб-приложении.

### Модели и связи
Category и Product задают сортировку через Meta.ordering. Order определяет варианты статуса и оплаты через TextChoices. related_name используется для обратных переходов: Category.products, Order.items и Product.reviews. __str__ возвращает понятное текстовое представление объекта.

В Order применяется timezone.now() при создании номера заказа и при записи даты нового статуса. Собственный UserManager поддерживает пользовательскую модель с входом по email.

### Запросы ORM
~~~python
queryset = (
    Product.objects.select_related('category')
    .exclude(is_active=False)
    .order_by('name')
)
~~~

Выборка находится в products/site_views.py: связанная серия загружается вместе с товаром, неактивные товары исключаются, результат сортируется по названию.

Поиск в products/filters.py использует name__icontains, article__icontains и description__icontains. Двойное подчёркивание задаёт оператор поиска или переход по связи, например order_items__order__status.

### Маршрутизация и пагинация
~~~python
def get_absolute_url(self):
    return reverse('product-detail', kwargs={'slug': self.slug})
~~~

Адрес строится по имени маршрута. Для HTML-управления товаром get_object_or_404 преобразует отсутствие объекта в HTTP 404. Paginator делит список на страницы по десять записей; PageNotAnInteger возвращает первую страницу, EmptyPage — последнюю.

### Регистрация и изображения
Регистрация реализована в users через POST /api/auth/register/. ImageField используется для изображения серии, товара и аватара. Для работы с изображениями подключена Pillow.

### Пояснения к основным понятиям
Миграция описывает изменение схемы базы. QuerySet — представление выборки, которое допускает последовательное добавление условий и обычно выполняется при обращении к результату. Именованные URL позволяют менять адрес маршрута без ручного изменения всех ссылок.

### Результат и вывод
В проекте реализованы модели, связи, фильтрация, исключение, сортировка, именованные URL, пагинация и регистрация. Собственные template tags и template filters в текущем коде отсутствуют; данный отчёт не заявляет их реализацию.

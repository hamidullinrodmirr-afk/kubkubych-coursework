# Отчёт по лабораторной работе 9

## Git: ведение проекта «КубКубыч»

### Цель и основание

Объяснить работу контроля версий на реальных изменениях проекта: просмотр состояния, анализ diff, выборочный коммит и публикация.

Источник темы — задание «Продвинутый Git», раздел «Весна 2026» [курса СДО](https://online.mospolytech.ru/course/view.php?id=15327). Приложенный PDF с упражнениями в доступных материалах отсутствует. Ниже разобраны подтверждённые операции, а не придуманный перечень упражнений из PDF.

Проверено 16.09.2026: ветка main, история коммитов, состав двух последних коммитов отчётов и состояние рабочей директории. Схемы поясняют логику, не заменяют скриншоты. Команды приведены в обычном виде для запуска из корня репозитория; в рабочем окружении использовалось также локальное для команды разрешение safe.directory, без изменения глобальной конфигурации.

## 1. Рабочая директория, индекс и коммит

Файл можно изменить, затем подготовить его к фиксации и только после этого создать коммит.

Место в проекте: Файлы в LAB и история Git.

~~~text
git status --short --branch
~~~

Рабочая директория содержит текущие файлы, индекс — выбранную версию для следующего коммита, коммит — снимок подготовленного состояния. git add не публикует файлы. После add последующая правка файла не попадёт в коммит без повторного добавления.

~~~text
Рабочий файл → git add → индекс → git commit → история
~~~

Состояние: Операции выполнялись при подготовке ЛР-3–ЛР-7.

## 2. Состояние ветки и несохранённые в коммите изменения

status показывает положение ветки и изменения относительно индекса и коммита.

Место в проекте: [LAB/lab-02-admin.md](lab-02-admin.md).

~~~text
git status --short --branch

# Фактический вывод до подготовки ЛР-8–ЛР-9:
## main...origin/main
 M LAB/lab-02-admin.md
~~~

В показанном выводе не указано отставание или опережение main относительно локального origin/main. Во второй строке M во второй колонке означает изменение рабочего файла без добавления в индекс. origin/main — локальное представление удалённой ветки, не непрерывная онлайн-проверка GitHub. Правка ЛР-2 сознательно оставалась вне коммитов следующих отчётов.

~~~text
main ↔ origin/main по локальным данным
ЛР-2 изменена → не добавлена → не входит в коммит
~~~

Состояние: Вывод получен реальной проверкой перед текущими изменениями.

## 3. Просмотр изменений

diff позволяет проверить содержимое до фиксации.

Место в проекте: [LAB/lab-06-django-4.md](lab-06-django-4.md) и [LAB/lab-07-django-5.md](lab-07-django-5.md).

~~~text
git diff -- LAB/lab-06-django-4.md LAB/lab-07-django-5.md
git diff --check -- LAB/lab-06-django-4.md LAB/lab-07-django-5.md
git diff --cached --stat
~~~

Обычный diff сравнивает рабочие файлы с индексом; --cached — индекс с HEAD. --check помогает выявить ошибки пробелов, но не проверяет правильность текста, секреты или работоспособность Django. Если файлы уже закоммичены и не изменены, текущий diff будет пустым; прошлое изменение нужно смотреть через show.

~~~text
Рабочие файлы ↔ индекс: diff
Индекс ↔ HEAD: diff --cached
~~~

Состояние: Выборочная проверка diff --check и состава индекса выполнялась перед коммитами отчётов.

## 4. Выборочное добавление файлов

Явные пути позволяют включить только нужные изменения.

Место в проекте: Только два отчёта ЛР-6 и ЛР-7.

~~~text
git add -- LAB/lab-06-django-4.md LAB/lab-07-django-5.md
git diff --cached --stat
~~~

При подготовке коммита ЛР-6–ЛР-7 были добавлены два файла, а изменённая ЛР-2 оставлена нетронутой. Это сохраняет границу задачи. Проверка --cached показывает весь подготовленный набор, в том числе ранее добавленные файлы, если они есть.

~~~text
ЛР-6, ЛР-7 → индекс
ЛР-2 → остаётся только в рабочей директории
~~~

Состояние: Подтверждено составом коммита 9ee723b.

## 5. Создание предметного коммита

Коммит фиксирует выбранные изменения под отдельным идентификатором.

Место в проекте: Коммит 9ee723b.

~~~text
git commit -m "Expand laboratory reports 6-7 with implementation walkthroughs"

# Зафиксированный результат:
[main 9ee723b] Expand laboratory reports 6-7 with implementation walkthroughs
2 files changed, 1102 insertions(+), 51 deletions(-)
~~~

Сообщение описывает содержание, а не только факт сохранения. Два файла — отчёты, код приложения не изменён. Статистика строк описывает размер diff и не измеряет качество отчёта. Повторять эту команду сейчас ради демонстрации не нужно: коммит уже существует.

~~~text
Индекс двух отчётов → commit → 9ee723b
~~~

Состояние: Результат подтверждён реальной командой commit и последующим show.

## 6. Просмотр истории и состава коммита

История позволяет связать изменение с конкретным этапом работы.

Место в проекте: Коммиты 3027e5c и 9ee723b.

~~~text
git log -5 --oneline
git show --stat --oneline 9ee723b
git show --stat --oneline 3027e5c
~~~

log показывает порядок коммитов, show — описание и затронутые файлы выбранного коммита. Проверено: 3027e5c содержит три отчёта ЛР-3–ЛР-5, 9ee723b — два отчёта ЛР-6–ЛР-7. Эти операции читают историю и не сбрасывают текущие правки.

~~~text
3027e5c → ЛР-3, ЛР-4, ЛР-5
9ee723b → ЛР-6, ЛР-7
~~~

Состояние: Обе проверки выполнены в текущем репозитории.

## 7. Публикация в удалённый репозиторий

push передаёт локальные коммиты в удалённую ветку.

Место в проекте: Ветка main на GitHub.

~~~text
git push origin main

# Подтверждённое обновление при отправке ЛР-6–ЛР-7:
3027e5c..9ee723b  main -> main
~~~

Отправка ЛР-6–ЛР-7 успешно обновила main до 9ee723b. Файлы, не включённые в коммит, через push не отправляются. Ранее сетевое ограничение помешало первой попытке отправки ЛР-3–ЛР-5; после предоставления сетевого доступа публикация прошла. Сетевая ошибка не означает потерю локального коммита.

~~~text
Локальный commit → push → удалённая main
Незакоммиченная ЛР-2 → не отправляется
~~~

Состояние: Публикация обоих этапов подтверждена успешными ответами Git.

## 8. Исключение локальных файлов

gitignore исключает определённые неотслеживаемые локальные файлы из обычного добавления.

Место в проекте: [.gitignore](../.gitignore).

~~~text
venv/
.venv/
db.sqlite3
media/
.env
.env.docker
*.swp
*.swo
~~~

В проекте не предназначены для коммита виртуальное окружение, локальная SQLite-база, загруженные файлы и swap-файлы Vim. gitignore не прекращает отслеживание уже добавленного файла и не удаляет секрет из истории. Поэтому перед коммитом всё равно нужен просмотр diff.

~~~text
Локальное окружение и загрузки → исключены из обычного add
Документы и исходники → контролируются Git
~~~

Состояние: Правила подтверждены содержимым .gitignore.

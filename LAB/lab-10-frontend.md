# Отчёт по лабораторной работе 10

## Фронтенд: доступность, адаптивность и печать

### Цель и основание разбора

Разобрать лабораторную на реализации интернет-магазина «КубКубыч»: показать каждый существенный пункт, его файл, код и последовательность работы.

Источник условий — раздел «Весна 2026» [курса СДО](https://online.mospolytech.ru/course/view.php?id=15327), перечень, ранее зафиксированный при разборе курса. Повторная сверка авторизованной страницы в этой редакции не выполнялась. Нумерация ниже поясняющая, не дословная нумерация задания.

Основание реализации — текущий исходный код. Фрагменты сокращены и могут не быть самостоятельными исполняемыми блоками. Схемы не являются скриншотами. Код, настройки и данные проекта при подготовке отчёта не изменялись.

### Общая логика

Django отдаёт HTML-шаблон, CSS задаёт экранное и печатное оформление, JavaScript получает данные и создаёт карточки. Доступность зависит не только от наличия атрибутов, но и от их согласованности с текущим состоянием интерфейса.

## 1. Структура документа и язык

### Что это

Общий шаблон задаёт язык, кодировку и место основного содержимого.

### Где находится

[templates/base.html](../templates/base.html) — Каркас HTML.

### Основной код

~~~django
<html lang="ru">
<meta charset="utf-8">
<meta name="viewport" content="width=device-width, initial-scale=1">
<main>{% block content %}{% endblock %}</main>
~~~

### Как работает

lang сообщает язык вспомогательным технологиям, charset — кодировку, viewport позволяет мобильному браузеру использовать реальную ширину экрана. header, nav, main и footer разделяют области страницы. Они не заменяют проверку порядка заголовков и всей семантики.

### Визуализация

~~~text
base.html → общая оболочка
index.html и другие шаблоны → основное содержимое
~~~

Состояние: Каркас реализован; полный аудит семантики не выполнен.

## 2. Адаптивные сетки

### Что это

Media queries меняют компоновку при уменьшении доступной ширины.

### Где находится

[static/css/style.css](../static/css/style.css) — Блок Responsive.

### Основной код

~~~css
@media (max-width: 768px) {
    .cards-grid { grid-template-columns: 1fr 1fr; gap: 16px; }
}
@media (max-width: 480px) {
    .cards-grid { grid-template-columns: 1fr; }
}
~~~

### Как работает

До 768 px карточки располагаются в две колонки, до 480 px — в одну. Отдельные правила на 1024 и 860 px перестраивают детали товара, оформление заказа, статистику и фильтры. Это правила CSS, а не доказательство отсутствия переполнений на всех устройствах.

### Визуализация

~~~text
Широкий экран → сетка
≤768 px → 2 колонки
≤480 px → 1 колонка
~~~

Состояние: Правила есть; визуальная проверка разных размеров не выполнена.

## 3. Мобильное меню

### Что это

Кнопка раскрывает скрытую на узком экране навигацию.

### Где находится

[static/js/app.js](../static/js/app.js) — Обработчик DOMContentLoaded.

### Основной код

~~~javascript
const burger = document.querySelector('.header__burger');
const nav = document.querySelector('.header__nav');
if (burger && nav) {
    burger.addEventListener('click', () => nav.classList.toggle('open'));
}
~~~

### Как работает

CSS показывает .header__nav.open, JavaScript переключает open. В base.html кнопке дано aria-label="Меню". Атрибуты aria-expanded и aria-controls не заданы и не обновляются: вспомогательным технологиям не сообщается раскрытое состояние. Обработчик закрытия по Escape отсутствует.

### Визуализация

~~~text
Кнопка Меню → open включён → ссылки видны
Повторный клик → open выключен → ссылки скрыты
~~~

Состояние: Переключение реализовано; доступность состояния меню неполная.

## 4. Подпись поиска

### Что это

Видимая подпись объясняет назначение поля и связана с ним через id.

### Где находится

[templates/index.html](../templates/index.html) — Форма home-search.

### Основной код

~~~html
<form class="home-search" action="/catalog/" method="get" role="search">
    <label for="home-search">Найти набор</label>
    <input id="home-search" name="search" type="search" placeholder="Название или артикул">
    <button class="btn btn--green" type="submit">Найти</button>
</form>
~~~

### Как работает

for у label совпадает с id input. role="search" обозначает область поиска, name="search" задаёт параметр GET. В каталоге часть фильтров использует лишь placeholder или варианты select без явной подписи: доступность главного поиска не означает доступность всех форм.

### Визуализация

~~~text
Подпись «Найти набор» → поле → кнопка Найти
~~~

Состояние: На главной реализовано; все поля сайта не проверены.

## 5. Изображения и кнопка избранного

### Что это

alt даёт текстовую альтернативу изображению, aria-label — имя кнопке с иконкой.

### Где находится

[static/js/app.js](../static/js/app.js) — productCard и toggleFavorite.

### Основной код

~~~html
<img class="card__image" src="${esc(p.image_url)}" alt="${esc(p.name)}" loading="lazy">
<button aria-label="${favText}" title="${favText}" onclick="toggleFavorite(${p.id}, this)">…</button>
~~~

### Как работает

productCard формирует alt из названия товара, а подпись кнопки — из исходного is_favorite. Декоративное SVG имеет aria-hidden="true". В toggleFavorite меняется класс и иногда видимый текст, но aria-label и title не обновляются. Для иконки после переключения имя может остаться прежним; aria-pressed также не задан.

### Визуализация

~~~text
Изображение → название товара
Иконка сердца → начальное имя действия
После клика → класс меняется, ARIA-имя не обновляется
~~~

Состояние: Начальные альтернативы есть; динамическое состояние доступности неполное.

## 6. Клавиатура и видимый фокус

### Что это

Пользователь должен видеть, какой элемент сейчас получает клавиатурный ввод.

### Где находится

[static/css/style.css](../static/css/style.css) — Правила .form-control и .search-input.

### Основной код

~~~css
.form-control:focus, .search-input:focus {
    border-color: var(--blue);
    box-shadow: 0 0 0 4px var(--blue-soft);
}
~~~

### Как работает

Для двух CSS-классов полей задано выделение фокуса. В основном правиле этих полей outline:none компенсируется border и box-shadow. Ссылки и кнопки являются нативными элементами, однако единый авторский :focus-visible для всех контролов не найден. Поле главного поиска не имеет этих двух классов: данный фрагмент не доказывает его специальное оформление фокуса.

### Визуализация

~~~text
Tab → поле с указанным классом → рамка и подсветка
~~~

Состояние: Стили части полей есть; весь порядок Tab и фокус всех контролов вручную не проверены.

## 7. Уменьшение движения

### Что это

Интерфейс учитывает системное предпочтение пользователя уменьшить анимацию.

### Где находится

[static/js/app.js](../static/js/app.js) — prefersReducedMotion, initMotion и initCounters.

### Основной код

~~~javascript
const prefersReducedMotion = () =>
    window.matchMedia && window.matchMedia('(prefers-reduced-motion: reduce)').matches;

// В initMotion:
if (prefersReducedMotion() || !('IntersectionObserver' in window)) return;
~~~

### Как работает

initMotion не запускает анимацию появления при reduce. initCounters в таком режиме сразу выводит итоговые значения. В CSS отдельный media-блок сокращает длительность animation и transition. Это не подтверждение полного отсутствия движения всех сторонних элементов. На текущей главной статические числа не имеют data-count, поэтому анимированные счётчики там не запускаются.

### Визуализация

~~~text
Системное reduce → без JS-анимации появления
Счётчики data-count → сразу итог
~~~

Состояние: Механизм реализован; визуальная проверка системного режима не выполнена.

## 8. Печатное представление

### Что это

Браузер применяет отдельный набор стилей при печати или сохранении страницы в PDF.

### Где находится

[static/css/style.css](../static/css/style.css) — @media print.

### Основной код

~~~css
@media print {
    @page { margin: 18mm; }
    body { color: #000; background: #fff; font-family: Arial, sans-serif; }
    .header, .footer, .header__actions, .header__burger, .btn, .home-search, .cart-row__remove,
    .product-detail__actions, .review-form, .alert { display: none !important; }
    a { color: #000; text-decoration: none; }
    .section { padding: 0; }
    .product-detail, .order-detail__grid { display: block; }
    .product-detail__media img { max-width: 110mm; }
    .product-detail__info, .order-detail__items, .order-detail__info { break-inside: avoid; }
}
~~~

### Как работает

Скрываются навигация и перечисленные действия, фон становится белым, некоторые сетки — блочными. break-inside просит избегать разрыва информационных блоков, но слишком большой блок всё равно может потребовать разрыва. Печатается уже загруженный DOM, поэтому нужно дождаться API. Это не PDF-действие ReportLab из ЛР-6 и не гарантия скрытия каждого интерактивного элемента сайта.

### Визуализация

~~~text
Экранный DOM → Ctrl+P → print CSS → бумага / браузерный PDF
~~~

Состояние: Печатные стили есть; предпросмотр и итоговый PDF визуально не проверены.

В коде есть адаптивные правила, подписи отдельных элементов, альтернативы изображений, уменьшение движения и печатное оформление. Не подтверждены контрастность, полный порядок клавиатурной навигации и визуальное качество печати. Найдены конкретные ограничения динамических ARIA-подписей и состояния меню; соответствие WCAG не заявляется.

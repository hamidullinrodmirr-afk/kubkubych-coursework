## 1. ManyToManyField и промежуточная модель

### Что это

Связь многие-ко-многим допускает много товаров у пользователя и много пользователей у товара.

### Где находится

[products/models.py](../products/models.py) — Product.favorited_by_users и Favorite.

### Основной код

~~~python
favorited_by_users = models.ManyToManyField(
    settings.AUTH_USER_MODEL,
    through='Favorite',
    related_name='favorite_products',
    blank=True,
    verbose_name='Добавили в избранное',
)
~~~

### Как работает

through указывает собственную модель Favorite. Она содержит user, product, created_at и UniqueConstraint для пары user/product. Дата относится к конкретному добавлению в избранное. В products/views.py используется get_or_create, повторная отметка не должна создавать вторую такую же пару. Поле этой связи не включено в ProductForm.

### Визуализация

~~~text
User ← Favorite(user, product, дата) → Product
~~~

Состояние требования: Реализовано в коде.

## 2. Цепочки QuerySet

### Что это

Методы можно последовательно объединять, уточняя одну выборку.

### Где находится

[products/site_views.py](../products/site_views.py) — product_manage_list.

### Основной код

~~~python
queryset = Product.objects.select_related('category').exclude(is_active=False).order_by('name')
~~~

### Как работает

select_related заранее загружает серию, exclude убирает неактивные товары, order_by сортирует по названию. Промежуточные вызовы не обязательно выполняют отдельные SQL-запросы: QuerySet обычно ленивый, результат запрашивается при потреблении. Изменяющие операции вроде update и delete выполняются иначе.

### Визуализация

~~~text
Product → загрузить серию → исключить неактивные → сортировать → вывод
~~~

Состояние требования: Реализовано в коде.

## 3. icontains: поиск подстроки

### Что это

Lookup ищет подстроку без учёта регистра в рамках возможностей СУБД.

### Где находится

[products/filters.py](../products/filters.py) — ProductFilter.filter_search.

### Основной код

~~~python
return queryset.filter(
    Q(name__icontains=value) | Q(article__icontains=value) | Q(description__icontains=value)
)
~~~

### Как работает

Условия объединены через OR: совпадения достаточно в названии, артикуле или описании. value приходит из фильтра search. ORM передаёт значение параметром запроса. Особенности регистронезависимого сравнения Unicode зависят от backend и его настроек, особенно в SQLite.

### Визуализация

~~~text
search → название ИЛИ артикул ИЛИ описание → совпавшие товары
~~~

Состояние требования: Реализовано в коде.

## 4. contains: отдельный lookup

### Что это

contains тоже ищет подстроку, но не выражает требование игнорировать регистр как icontains.

### Где находится

[products/filters.py](../products/filters.py) — Сравнение с используемым filter_search.

### Основной код

~~~python
Q(name__icontains=value)
~~~

### Как работает

В текущем поиске используется icontains. Отдельное применение __contains в прикладных выборках не обнаружено. Поведение чувствительности к регистру зависит от СУБД и collation; нельзя обещать одинаковое различие для SQLite и PostgreSQL. Показанная строка — существующий код icontains, не доказательство contains.

### Визуализация

~~~text
Требование contains → отдельного примера нет
Реальный поиск → icontains
~~~

Состояние требования: Отдельный contains не реализован.

## 13. is_valid: проверка формы

### Что это

is_valid запускает проверку формы и возвращает результат.

### Где находится

[products/site_views.py](../products/site_views.py) — product_create.

### Основной код

~~~python
if request.method == 'POST' and form.is_valid():
    product = form.save(commit=True)
~~~

### Как работает

Сохранение выполняется только при POST и успешной проверке. Для ModelForm проверяются поля формы и связанные ограничения модели, включая применимые проверки уникальности. При ошибке код доходит до render той же формы, и её ошибки доступны шаблону. Сервер не должен доверять только min/max HTML.

### Визуализация

~~~text
POST → is_valid
        ├─ True → save → redirect
        └─ False → форма с ошибками
~~~

Состояние требования: Реализовано в коде.

### Что это

Media объявляет CSS и JavaScript, необходимые форме или её виджетам.

### Где находится

[products/forms.py](../products/forms.py) — ProductForm.Media.

### Основной код

~~~python
class Media:
    css = {'all': ('css/style.css',)}
~~~

### Как работает

Здесь объявлен CSS для всех типов отображения. Для вывода зависимостей обычно нужен {{ form.media }} в шаблоне. В manage_form.html такого вывода нет. Общий stylesheet уже подключён базовым шаблоном, но это другой механизм, не доказательство использования Media.

### Визуализация

~~~text
Media объявлен → form.media
                      ↓
Вывод в шаблоне → отсутствует
Общий CSS base.html → отдельное подключение
~~~

Состояние требования: Частично: объявление есть, вывод form.media не реализован.

## Ответы на контрольные вопросы

## Вопрос 1. Что делает F?

### Что это

F ссылается на значение поля внутри выражения SQL.

### Где находится

[analytics/services.py](../analytics/services.py) — products_report, расчёт revenue.

### Основной код

~~~python
revenue=Sum(F('unit_price') * F('quantity'), output_field=DecimalField()),
~~~

### Как работает

База умножает цену единицы позиции на количество, затем Sum складывает результаты. В top_selling до этого выбираются позиции доставленных заказов и задаётся группировка через values. Вычисление не требует Python-цикла по позициям. F — не функция получения готового числа в Python.

### Визуализация

~~~text
unit_price × quantity → сумма по группе → revenue
~~~

Состояние требования: Реализовано в коде.

## Вопрос 2. Что означает Http404?

### Что это

Http404 сигнализирует, что запрошенный ресурс не найден.

### Где находится

[products/site_views.py](../products/site_views.py) — product_update / product_delete.

### Основной код

~~~python
product = get_object_or_404(Product, pk=pk)
~~~

### Как работает

get_object_or_404 возвращает товар либо поднимает Http404 при отсутствии записи. Django формирует ответ 404. Это не ошибка валидации формы и не отказ в правах: проверка роли находится в декораторе и относится к другому сценарию.

### Визуализация

~~~text
ID → найден: продолжить
   → отсутствует: HTTP 404
~~~

Состояние требования: Реализовано в коде.

## Вопрос 3. Как проходит загрузка файла?

### Что это

Браузер отправляет содержимое выбранного файла как часть multipart-запроса.

### Где находится

[templates/products/manage_form.html](../templates/products/manage_form.html) — Атрибуты формы.

### Основной код

~~~django
<form method="post" enctype="multipart/form-data">
    {% csrf_token %}
    <!-- Поля выводятся циклом формы. -->
</form>
~~~

### Как работает

Представление передаёт request.FILES в ProductForm, форма проверяет данные, save сохраняет модель и файл средствами хранилища. image использует ImageField, specification_file — FileField. В базе остаётся имя файла. Наличие этого пути обработки не заменяет ограничения размера, допустимых форматов и проверку безопасности загрузок.

### Визуализация

~~~text
Выбор файла → multipart POST → request.FILES
          → проверка формы → storage + путь в базе
~~~

Состояние требования: Путь загрузки реализован; дополнительные собственные ограничения файла не заявляются.

Показаны связь через Favorite, операции QuerySet, отдельные настройки формы и работа её шаблона. ## Демонстрация в интерфейсе

Для демонстрации формы нужно после сессионного входа администратора открыть /manage/products/create/, проверить подписи, числовые поля, многострочное описание, подсказку спецификации и загрузку файла. Ошибку артикула можно проверить на повторном значении существующего товара. QuerySet-примеры относятся к разным сценариям: каталог, аналитика, проверка покупки и действия модерации; не все операции видны на одной странице. Массовое update и delete изменяют данные, поэтому демонстрировать их следует только на согласованных учебных записях. Эти действия при подготовке отчёта не выполнялись.

Реальные авторизованные скриншоты в эту редакцию не включены. Наличие реализации подтверждается кодом; качество UI и содержимого файлов требует отдельной ручной проверки.

## Консольный редактор Vim

### Цель и основание

Рассмотреть режимы, навигацию, поиск и редактирование в Vim на файлах Django-проекта «КубКубыч».

Источник темы — раздел «Весна 2026» [курса СДО](https://online.mospolytech.ru/course/view.php?id=15327), ранее просмотренный при анализе лабораторных. Точный перечень упражнений в доступных материалах отсутствует. Поэтому пункты ниже — объяснение работы редактора, а не восстановленное задание преподавателя.

Подтверждено: установлен Vim 9.2 в составе Git for Windows, проверен запуск команды --version. Редактирование файлов в интерактивном Vim и скриншоты не выполнялись. Команды ниже являются примерами демонстрации; схемы не являются скриншотами.

### Как Vim связан с проектом

Vim редактирует текст файлов, но не выполняет бизнес-логику Django. Модели описаны в products/models.py, форма — в products/forms.py, обработка запросов — в products/site_views.py. Сохранение Python-файла в редакторе не применяет миграции базы.

## 1. Открытие файла

Редактор открывает текст формы товара. -R включает режим read-only для безопасного просмотра.

Файл: [products/forms.py](../products/forms.py).

~~~text
# PowerShell из корня проекта:
& "C:\Program Files\Git\usr\bin\vim.exe" -R products/forms.py
~~~

В PowerShell оператор & запускает исполняемый файл, путь с пробелами заключён в кавычки. Команда vim может не находиться через PATH, поэтому указан полный путь. Read-only не является абсолютной защитой от принудительной записи; для просмотра не следует использовать команды с !.

~~~text
PowerShell → vim.exe → текст ProductForm
~~~

Состояние: Наличие исполняемого файла проверено; интерактивное открытие этим примером не выполнено.

## 2. Режимы

Одна клавиша имеет разное назначение в разных режимах.

Файл: [products/forms.py](../products/forms.py).

~~~text
i       перейти к вводу перед курсором
Esc     вернуться к обычным командам
:       начать команду редактора
v       выделять символы
V       выделять строки
~~~

В Normal клавиша i переключает режим, в Insert она вводит букву. Visual выделяет текст. После Esc можно вводить команды навигации; команда после двоеточия выполняется Enter. Изменения следует демонстрировать на отдельной учебной копии, не в исходном файле проекта.

~~~text
Normal → i → Insert → Esc → Normal
Normal → v → Visual → Esc → Normal
~~~

Состояние: Теоретическое объяснение; ввод в исходники не выполнялся.

## 3. Навигация

Перемещение курсора не меняет содержимое файла.

Файл: [products/forms.py](../products/forms.py), класс ProductForm.

~~~text
h j k l     влево, вниз, вверх, вправо
w / b       вперёд / назад по словам
gg / G      первая / последняя строка
0 / $       начало / конец строки
:20         перейти к строке 20
~~~

Навигация помогает найти Meta, widgets или clean_article. Число перед движением повторяет его: 5j перемещает на пять строк вниз, если строки существуют. Номер строки — ориентир, который может меняться после редактирования.

~~~text
ProductForm → Meta → widgets → clean_article
~~~

Состояние: Приведены команды, не журнал выполненных движений.

## 4. Поиск метода

Поиск находит нужный текст без ручного пролистывания.

Файл: [products/forms.py](../products/forms.py), clean_article.

~~~text
/clean_article    затем Enter
n                 следующее совпадение
N                 совпадение в обратном направлении
:nohlsearch       снять подсветку поиска
~~~

В форме clean_article берёт артикул из cleaned_data, удаляет крайние пробелы и переводит в верхний регистр. Поиск только перемещает курсор, а не вызывает метод. Если совпадений нет, Vim сообщает об отсутствии шаблона.

~~~text
/clean_article → определение метода → чтение кода
~~~

Состояние: Метод подтверждён исходником; поиск в интерактивном Vim не зафиксирован.

## 5. Копирование и удаление

Команды работают с текстом буфера редактора.

Файл: Учебная копия [products/forms.py](../products/forms.py), не исходник.

~~~text
yy      скопировать строку
p       вставить после текущей строки
dd      удалить строку в регистр
u       отменить изменение
Ctrl+r  вернуть отменённое изменение
~~~

yy и dd используют регистр Vim, который не обязан совпадать с системным буфером Windows. dd меняет текст, yy — нет. p вставляет содержимое регистра; u позволяет отменить изменение. Удаление строки Python может нарушить синтаксис или отступы.

~~~text
Строка → yy → регистр → p → копия
Строка → dd → удалена → u → восстановлена
~~~

Состояние: Пример для отдельной копии; код проекта не удалялся.

## 6. Замена текста

Команда заменяет совпадения с подтверждением каждого изменения.

Файл: Учебная копия файла Markdown, не исходный код.

~~~text
:%s/old/new/gc
~~~

% задаёт весь буфер, s — подстановку, g — все совпадения в строке, c — запрос подтверждения. old трактуется как шаблон регулярного выражения, не всегда как буквальная строка. Для демонстрации можно использовать нейтральный учебный текст; массовую замену в проекте эта команда не разрешает.

~~~text
Совпадение old → подтвердить? → заменить / пропустить
~~~

Состояние: Пример замены, не выполненная массовая правка.

## 7. Сохранение и выход

Буфер в памяти и сохранённый файл — разные состояния.

Файл: Учебный файл; для просмотра исходника достаточно :q.

~~~text
:w      записать файл
:q      выйти, если нет несохранённых изменений
:wq     записать и выйти
:q!     выйти, отбросив несохранённые изменения
:help   открыть справку
~~~

Изменение текста ещё не означает запись на диск. :w сохраняет, :wq завершает работу после сохранения. :q! может потерять несохранённый текст и должен использоваться осознанно. Сохранение модели не обновляет схему БД: это отдельные makemigrations и migrate.

~~~text
Буфер → :w → файл на диске
Файл модели → отдельные миграции → схема БД
~~~

Состояние: Описание команд; сохранение проекта через Vim не заявляется.

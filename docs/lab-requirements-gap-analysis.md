# Gap-анализ курсовой работы для лабораторных

Дата анализа: 15.09.2026. Проект: «КубКубыч» — интернет-магазин LEGO-наборов.

## Границы и достоверность

Подтверждённые факты ниже основаны на статической проверке репозитория: исходного кода, шаблонов, конфигурации, README и истории Git. Исходники не изменялись.

Требования сверены с заданиями 1–14 из раздела «Весна 2026» курса «Веб-технологии 241-671, 241-672» в СДО 15.09.2026. На момент просмотра в СДО у каждого задания отображалось «Ответы на задание еще не представлены» и «Не оценено». Это статус заданий в СДО, а не вывод о качестве кода.

## Краткая оценка проекта

Проект является развёрнутым Django-приложением, а не статичной вёрсткой. Реализованы серверный HTML-интерфейс и REST API, аутентификация и роли, каталог, фильтрация, корзина, заказ, отзывы, избранное, административная аналитика, Docker Compose и фоновые задачи Celery. По масштабу он потенциально может закрывать несколько лабораторных, если в них допускается Django и совпадают предметные требования.

Подтверждённые артефакты:

| Направление | Что найдено | Доказательство |

## Минимальный приоритет доработок

1. Подготовить материалы, без которых код не может быть зачтён: отчёт по заданию 1, отчёты Vim/Git/Frontend, пояснительную записку задания 14.
2. Закрыть полностью отсутствующие технические пункты: PDF/`FileField`/cache (задание 6), simple-history и import-export (задание 13), print stylesheet (задание 10).
3. Для заданий 3, 4 и 7 добавить требуемые именно Django-артефакты: формы, template tags, pagination, `ManyToManyField(through=...)` и debug toolbar. REST API не заменяет эти явно названные требования.
4. Для заданий 11–12 сделать видимый сайтовый CRUD и поиск на главной; наполнить каждую используемую таблицу минимум 10 записями либо получить у преподавателя подтверждение иного правила для служебных таблиц.

## Выявленные разрывы, не зависящие от текста лабораторных

### Блокирующие для доказательства работоспособности

1. Команды `python manage.py check` и `python manage.py test` не стартуют. Системный `python` отсутствует в PATH, а `venv\\Scripts\\python.exe` ссылается на отсутствующий интерпретатор `C:\\Users\\????\\AppData\\Local\\Programs\\Python\\Python311\\python.exe`. Следовательно, заявленные в README 53 сценария не были подтверждены этим анализом.
2. Не найден единый воспроизводимый сценарий проверки проекта без локального venv: в README указан `python`, но не зафиксирован рабочий интерпретатор или lock-файл.

### Недостающие материалы для сдачи

1. Не найдено сопоставление «лабораторная → критерий → файл/скриншот/сценарий демонстрации».
2. Не найдены ER-диаграмма, схема архитектуры и пользовательские сценарии. Если они входят в задание, их нужно подготовить из подтверждённых моделей и маршрутов, а не из предположений.
3. Не найдены результаты фактического запуска: скриншоты UI, API-запросов, тестов и Docker Compose. Наличие кода не заменяет доказательство выполнения.

### Технические замечания для ручной проверки

1. `kubkubych/settings.py:13` задаёт development-ключ по умолчанию, а `kubkubych/settings.py:15` — `DEBUG=True`. Это допустимо только для локальной разработки; настройки нужно явно разделить для публичного развёртывания.
2. `kubkubych/settings.py:29` включает `send_default_pii=True` при подключённом Sentry. Перед публикацией нужно подтвердить, допустима ли передача персональных данных и есть ли согласие/политика обработки.
3. `docker-compose.yml:11` содержит пароль PostgreSQL прямо в Compose. Это не секрет для учебного локального стенда, но не должно переноситься в публичный репозиторий или развёртывание без переменной окружения.
4. `README.md:67-71` раскрывает демонстрационные учётные данные. Для локальной демонстрации это может быть приемлемо; для опубликованного доступного стенда нужно заменить пароль, ограничить доступ или описать безопасный bootstrap.
5. В клиентском коде есть inline-обработчики `onclick`; это не ошибка само по себе, но может не соответствовать требованиям лабораторной к разделению HTML/JS. Например: `templates/cart/index.html`, `templates/catalog/detail.html`, `static/js/app.js`.
